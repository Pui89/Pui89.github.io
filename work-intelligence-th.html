04 · VERIFYทดสอบและตรวจทาน

รันการตรวจสอบ บันทึกข้อผิดพลาด และเปรียบเทียบผลที่คาดกับผลจริง

ต้องมีมนุษย์อนุมัติก่อน Merge, Release, สื่อสารภายนอก หรือดำเนินการเสี่ยง

GITHUB EVENTS

ตรวจ Pull Request และ Commit

  • รันทดสอบเมื่อเปิดหรืออัปเดต Pull Request
  • ตรวจเอกสาร ลิงก์ JSON และสัญญาข้อมูลโครงการ
  • เผยแพร่ผลตรวจและ artifacts เฉพาะเมื่อมีประโยชน์

ต้องตรวจ workflow ที่มีอยู่ก่อนเพิ่มหรือเปลี่ยนระบบอัตโนมัติ

ISSUE EVENTS

รับงานอย่างมีโครงสร้าง

  • ใช้ issue templates สำหรับ bug งานวิจัย และข้อเสนอวิศวกรรม
  • ติด labels ตามโครงการ ความสำคัญ ความเสี่ยง และสถานะหลักฐาน
  • เชื่อม issue กับ branch, commit และ pull request

ห้ามใส่ secrets ข้อมูลส่วนบุคคล หรือข้อมูลปฏิบัติการอ่อนไหวใน public issues

RELEASE EVENTS

บันทึกหลักฐานและ Release

  • สร้างสรุปผลตรวจสอบที่อ้างอิง commit เฉพาะ
  • แยก passed, failed, skipped และ unknown
  • ให้มนุษย์ทบทวนก่อน release หรือเผยแพร่

CI ผ่านหมายถึงเฉพาะการตรวจสอบที่ระบุผ่านสำหรับ commit นั้น

REPOSITORY EVENTS

บำรุงรักษาและความยืดหยุ่น

  • ทบทวน dependency updates และการเปลี่ยนใบอนุญาต
  • ตรวจ branch protection และสิทธิ์ workflow แบบ least privilege
  • รักษาประวัติเวอร์ชันและทดสอบขั้นตอนกู้คืน

ห้ามเปิดใช้บริการแบบคิดค่าบริการหรือ third-party actions ใหม่โดยไม่ตรวจต้นทุนและความน่าเชื่อถือ

ขอบเขตอัตโนมัติและการอนุมัติ

ทำอัตโนมัติได้หลังทบทวน

งานซ้ำที่มีความเสี่ยงต่ำ

อ่านเอกสารสาธารณะ รันทดสอบ ตรวจรูปแบบ สร้างรายงานจากบันทึกที่ยืนยันแล้ว ตรวจลิงก์เสีย และเตรียม pull request แบบร่าง

ต้องได้รับอนุมัติจากมนุษย์

การดำเนินการที่มีผลกระทบ

Merge หรือ Release เปลี่ยน branch protection ลบหรือเขียนทับข้อมูล เปลี่ยน credentials หรือ permissions ติดต่อพันธมิตรภายนอก ใช้จ่ายเงิน หรือสั่งงานฮาร์ดแวร์จริง

สัญญาด้านต้นทุนศูนย์และหลักฐาน

ต้นทุนและความปลอดภัย

  • ไม่ใช้ paid API, subscription, cloud GPU, model download หรือ metered service เป็นค่าเริ่มต้น
  • ไม่ใส่ secrets ใน source code, public issues, logs หรือ test fixtures
  • ใช้ least privilege, credentials อายุสั้นเมื่อจำเป็น และช่องทางเพิกถอน
  • ตรวจ GitHub Actions minutes, artifact retention และใบอนุญาต external actions ก่อนขยายระบบ

หลักฐานและความถูกต้อง

  • แนบ repository, branch, commit SHA, วันที่ คำสั่ง และผลลัพธ์ในบันทึกตรวจสอบ
  • แยก measured, synthetic, estimated, proposed และ unknown
  • ห้ามเปลี่ยนข้อมูลที่ขาดให้เป็นผลผ่าน หรือสร้างเปอร์เซ็นต์ความคืบหน้าขึ้นเอง
  • ทำงานบน feature branch และใช้ pull request ภายใต้ branch protection
ข้อจำกัดปัจจุบัน: หน้านี้เป็นเอกสารและการนำเสนอผ่านเว็บไซต์เท่านั้น ยังไม่มี task backend ไม่ได้รัน Agent ไม่ได้ตั้งเวลาตรวจติดตาม ไม่ได้เปลี่ยนการตั้งค่า repository และไม่ได้สั่งรัน GitHub Actions
