# PUI89 AI Robotics — Support Milestones

This page turns support and sponsorship conversations into concrete, reviewable work packages. These are proposed milestones, not completed results or promised deadlines. Scope and timing must be agreed with any supporter before work starts.

## Priority 1 — Establish a trustworthy coconut-image benchmark

**Why it matters:** a credible agricultural AI project needs documented data rights, reviewed labels, a held-out evaluation set, and results that another person can reproduce.

**Support that helps**
- A coconut grower, agricultural researcher, or data partner who can discuss image needs and permission terms.
- An experienced computer-vision reviewer to inspect annotation quality and evaluation design.
- Open-source contributors who can reproduce the documented checks.

**Acceptance evidence**
- A source and reuse-rights record for every included image.
- Human-reviewed annotations and a documented policy for ambiguous examples.
- A leakage-aware, held-out split with a saved manifest.
- An actual detector and checkpoint identified by provenance, with the exact command and environment recorded.
- Reproducible precision, recall, F1 at declared thresholds, runtime context, and representative false positives and false negatives—or a clear report that inference remains blocked.

**Boundary:** no model-performance claim is made until this work is run on eligible data and its outputs are inspected.

## Priority 2 — Improve the local prototype and reproducibility

**Why it matters:** researchers and potential partners need a clear path to install, run, inspect, and reproduce the software.

**Support that helps**
- Python and computer-vision code review.
- Testing on Windows and other supported environments.
- Documentation, accessibility, packaging, and automated-test contributions.

**Acceptance evidence**
- A documented installation and run path.
- A passing, clearly reported automated test suite on declared environments.
- A reproducible example with expected output and known limitations.
- Issues and defects tracked publicly where appropriate, with sensitive information excluded.

**Boundary:** passing software tests demonstrates tested software behaviour, not orchard-level accuracy or commercial readiness.

## Priority 3 — Validate a supervised orchard workflow

**Why it matters:** practical value must be measured against a real user need, not inferred from a concept image.

**Support that helps**
- A grower or agricultural organisation willing to discuss one specific inspection or harvest-planning workflow.
- Permissioned, representative images and domain expertise.
- A mentor who can help define an evaluation protocol and operator feedback process.

**Acceptance evidence**
- A written workflow definition and partner-approved success measures.
- Agreed data permissions, privacy boundaries, responsibilities, and risk review.
- Offline or human-reviewed evaluation with recorded limitations and user feedback.
- A decision record describing whether the evidence supports continuing, changing scope, or stopping.

**Boundary:** this milestone does not include autonomous cutting or unsupervised physical operation. Any later hardware trial requires separate engineering and safety approval.

## Ways to contribute

| Contribution | Immediate use |
|---|---|
| Technical mentorship | Review experiment design, architecture, evaluation, or safety assumptions |
| Open-source code or documentation | Reproduce tests, improve usability, fix bugs, or clarify setup |
| Data and annotation support | Provide appropriately permissioned images and expert review |
| Pilot discovery | Help identify a real workflow and measurable success criteria |
| In-kind equipment or lab access | Evaluate whether existing cameras, sensors, or robotics facilities suit a defined test |
| Sponsorship or grant introduction | Discuss a written scope, eligible costs, deliverables, reporting, and ownership terms |

## Accountability

- No sponsor, grant, customer, pilot, or field-validation outcome is implied by this document.
- Support should be tied to a written scope, measurable acceptance criteria, ownership/licensing terms, and a reporting plan.
- Any proposed spend, paid service, equipment purchase, or recurring commitment requires explicit approval.
- Public acknowledgements and logos require permission.
- Data and model licences must be checked before redistribution or commercial use.
