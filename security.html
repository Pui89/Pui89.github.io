PUI89 · Security & Trust

Security by design. Evidence before claims.

A practical security baseline for the PUI89 website and seven project repositories. It reduces exposure; it does not promise immunity from attack.

What we protect against

  • Unauthorised repository or website changes.
  • Malicious dependencies, compromised build actions and unsafe downloaded files.
  • Credential leaks, secret exposure and accidental publication of sensitive data.
  • Malware, tampered assets, unsafe external scripts and supply-chain compromise.
  • Untrusted AI outputs or inputs crossing human and safety boundaries.

Baseline controls

  • Pull-request review and protected default branches where repository settings permit.
  • Least-privilege CI permissions and no secrets exposed to untrusted pull requests.
  • Dependency, action, licence and provenance review before adoption.
  • Input validation, file-size/type limits, integrity hashes and conservative failure handling where applicable.
  • Human approval for consequential decisions; AI proposals do not gain automatic physical authority.
  • Verified backups or known-good revisions and a documented recovery process.

Report a vulnerability privately

Do not post exploit details, passwords, tokens, personal information or sensitive records in public issues. Use GitHub private vulnerability reporting when available, or contact the maintainer privately through the official PUI89 GitHub profile. Include the affected repository/file, commit, impact and safe reproduction steps.

Important limitations

Automated scans detect only certain classes of issues and can miss new or sophisticated threats. A green CI check does not prove code safety or establish malware absence. No independent penetration test or security certification is claimed.
