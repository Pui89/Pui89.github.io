Evidence interpretation standard

Software checks

Unit, schema, contract and workflow checks establish only the behavior covered by their test cases and fixtures.

Simulation

Simulation results depend on the model, assumptions, scenario coverage and reproducibility. They do not equal field validation.

Real-world validation

Requires representative data or hardware, documented protocols, independent measurements, safety review and appropriate approvals.

Evidence integrity

Every material result should identify its source, timestamp, project commit, test version, limitations and failure cases.

Shared engineering principles

Observation → WorldState → ActionProposal → Safety Gate → FailureReport, with an Evidence Passport recording provenance and limitations. Cross-project integration is considered complete only when each repository has a manifest, conformance fixtures and a report tied to its actual commit.

Dashboard scope: read-only public metadata. Private repository checks, full test logs, billing data, repository settings and live deployment status are not exposed here and must not be inferred.
