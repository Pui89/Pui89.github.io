# Documentation Guidelines

Every project README and technical document should use the same information architecture:
- Project name, one-sentence purpose and current maturity.
- Problem, intended users and operating context.
- Current implementation and reproducible evidence.
- Proposed features and future work, clearly separated.
- Architecture and interfaces.
- Safety, limitations, risks and assumptions.
- Setup and test instructions with dependency/cost notes.
- Dataset/model/software provenance and licences.
- Roadmap with measurable acceptance criteria.
- Website/repository links, bilingual links and verified QR code where appropriate.

Use consistent headings, tables, diagrams, terminology, units, dates and status labels. Include evidence links beside claims. Never invent benchmark results, datasets, partnerships, customers, certifications or physical capabilities.
