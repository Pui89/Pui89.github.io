# Website Guidelines

## Page system
Use shared navigation, footer, content width, heading scale, card, button, status, image and call-to-action patterns. Keep pages lightweight and usable without JavaScript where practical.

## Required project-page structure
1. Canonical project name and concise purpose.
2. Problem and intended beneficiaries/users.
3. Current maturity/status.
4. What is implemented and what has actually been tested.
5. What remains conceptual or proposed.
6. Limitations, safety considerations and evidence links.
7. Next measurable milestone.
8. Appropriate collaboration/support contact route.
9. Reciprocal links to the matching GitHub repository and English/Thai page.
10. QR code only when the destination is correct and independently verified.

## Responsive rules
Design mobile-first. Avoid fixed-width layouts, horizontal scrolling, tiny captions and text embedded in images. Use responsive images with intrinsic dimensions and lazy loading below the fold.

## Metadata and navigation
Use descriptive page titles and meta descriptions, canonical URLs, reciprocal hreflang for genuine translations, Open Graph metadata, a valid sitemap and useful internal links. Do not claim Google indexing or ranking without direct evidence.

## Content governance
Maintain an inventory of public pages and matching repositories. Before replacing/removing an image or page section, search references and preserve a recoverable copy. Do not bulk-rewrite all pages in one change. Use focused PRs and verify both language variants after each rollout.
