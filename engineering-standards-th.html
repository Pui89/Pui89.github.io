03 · ระบบ AI ทำงานอย่างไร

PUI89 ใช้แนวทางวิศวกรรมร่วมกัน และปรับเทคโนโลยีให้เหมาะกับแต่ละผลิตภัณฑ์ ไม่ได้หมายความว่าทุกโครงการใช้เทคโนโลยีทุกชนิดเหมือนกัน

การรับรู้ (Perception)

ตรวจสอบคุณภาพภาพ ตรวจจับ จำแนก แบ่งส่วน ติดตามวัตถุ และประเมินมิติเชิงพื้นที่เมื่อมีข้อมูลและเซนเซอร์ที่เหมาะสม

บริบทและความเข้าใจ

เชื่อมโยงข้อมูลสังเกตกับเวลา สถานที่ สภาพการทำงาน คุณภาพเซนเซอร์ และข้อจำกัดของระบบ

การผสานข้อมูลหลายรูปแบบ

เชื่อมโยงข้อมูลจากกล้อง ความลึก ความร้อน ระยะทาง สภาพแวดล้อม และเซนเซอร์อื่นที่ได้รับอนุญาต พร้อมแหล่งที่มาและความไม่แน่นอน

Perception & Task Intelligence

แปลงข้อมูลที่รับรู้ให้เป็นการประเมินตามภารกิจ ลำดับความสำคัญ การแจ้งเตือน และข้อเสนอที่มนุษย์ตรวจทานได้

Edge AI และประสิทธิภาพการประมวลผล

เลือกขนาดโมเดลและจัดสรรงานให้เหมาะกับ CPU, GPU, NPU, MCU หน่วยความจำ พลังงาน และข้อจำกัดด้านความร้อน

ความปลอดภัย การวินิจฉัย และการกู้คืน

ตรวจจับความผิดปกติ ข้อมูลเก่า และความไม่แน่นอน สนับสนุนการหยุดอย่างปลอดภัย การตรวจทานโดยมนุษย์ รายงานข้อผิดพลาด และแผนกู้คืน

04 · วงจรการพัฒนาทางวิศวกรรม

เส้นทางที่มีวินัยตั้งแต่ความต้องการของผู้ใช้ ไปสู่ความสามารถที่มีหลักฐานรองรับ

ค้นหาปัญหา

ระบุผู้ใช้ ปัญหา บริบท ข้อจำกัด และผลลัพธ์ที่วัดได้

กำหนดข้อกำหนด

กำหนดความต้องการ อินเทอร์เฟซ อันตราย ขอบเขตความเป็นส่วนตัว และเกณฑ์ยอมรับ

ออกแบบ

เลือกสถาปัตยกรรม ส่วนประกอบ และเครื่องมือ Open Source หลังตรวจสอบใบอนุญาตและแหล่งที่มา

พัฒนา

สร้างโมดูลขนาดเล็กที่ตรวจสอบได้ พร้อม dependencies และสัญญาข้อมูลที่มีเวอร์ชัน

ทดสอบ

ตรวจสอบกรณีปกติ ข้อมูลไม่ถูกต้อง กรณีขอบ ข้อมูลขาดหาย และเส้นทางความล้มเหลว

จำลอง

ใช้สถานการณ์และสมมติฐานที่บันทึกไว้ การจำลองไม่ใช่การตรวจสอบทางกายภาพ

ตรวจสอบในสภาพจริง

ทดสอบด้วยหลักฐานที่เหมาะสม ภายในขอบเขตการใช้งานที่กำหนด

ปรับปรุง

ทบทวนผลลัพธ์ เหตุการณ์ ข้อเสนอแนะ การบำรุงรักษา และข้อกำหนดที่เปลี่ยนไป

05 · คุณภาพ ความปลอดภัย และความไว้วางใจ

ความน่าเชื่อถือ

กำหนดขอบเขตการทำงาน ทดสอบซ้ำได้ วินิจฉัยปัญหา จัดการความผิดพลาด และบันทึกพฤติกรรมการกู้คืน

ความปลอดภัยตั้งแต่การออกแบบ

ระบุอันตราย กำหนดมาตรการควบคุม ใช้พฤติกรรมแบบระมัดระวังเมื่อไม่แน่ใจ และให้มนุษย์อนุมัติการกระทำที่มีผลสำคัญ

ความเป็นส่วนตัวและความมั่นคงปลอดภัย

เก็บข้อมูลเท่าที่จำเป็น ควบคุมสิทธิ์ จัดการข้อมูลอย่างปลอดภัย ตรวจสอบ dependencies และปกป้องข้อมูลอ่อนไหว

การอธิบายได้

แสดงหลักฐานที่เกี่ยวข้อง ระดับความเชื่อมั่น ความไม่แน่นอน เวลา และเหตุผลของคำเตือนหรือคำแนะนำ

การบำรุงรักษา

สถาปัตยกรรมแบบโมดูล เอกสารชัดเจน ประวัติเวอร์ชัน การทดสอบซ้ำได้ และการวางแผนบริการ

การเข้าถึงและประสบการณ์ใช้งาน

หน้าจอเข้าใจง่าย การแจ้งเตือนชัดเจน ขั้นตอนใช้งานเหมาะสม และคำนึงถึงผู้ใช้ที่หลากหลาย

06 · หลักฐานและระดับความพร้อม

ข้อความที่สื่อสารต้องตรงกับสิ่งที่ทำแล้วจริง ใช้คำศัพท์ชุดเดียวกันในหน้าโครงการ repository รายงาน และการสาธิต

สถานะความหมายสิ่งที่ยังยืนยันไม่ได้
Proposed · เสนอแนวคิดแนวคิดหรือความสามารถที่วางแผนไว้การพัฒนาหรือสมรรถนะ
Specified · กำหนดข้อกำหนดมีเอกสารข้อกำหนด ขอบเขต และวิธีรับรองผลซอฟต์แวร์หรือฮาร์ดแวร์ที่ทำงานได้แล้ว
Implemented · พัฒนาแล้วมีโค้ดหรือกลไกควบคุมที่ระบุได้ความถูกต้องในทุกสภาพแวดล้อม
Tested · ทดสอบแล้วมีการทดสอบที่ระบุชื่อและเงื่อนไขความพร้อมภาคสนามหรือใบรับรอง
Simulated · จำลองแล้วรันสถานการณ์ที่บันทึกไว้ในสภาพแวดล้อมจำลองความปลอดภัยหรือสมรรถนะจริง
Validated · ตรวจสอบยืนยันแล้วมีหลักฐานที่เหมาะสมรองรับการใช้งานและขอบเขตที่ระบุความเหมาะสมทุกกรณีหรือการอนุมัติตามกฎหมาย
Certified · ได้รับการรับรองหน่วยงานที่มีอำนาจออกใบรับรองที่เกี่ยวข้องแล้วการกล่าวอ้างนอกขอบเขตใบรับรอง

หากไม่มีหลักฐาน หลักฐานยังไม่ครบ หรือยังไม่ได้ตรวจสอบ ให้ระบุว่า “Unknown” หรือ “Not tested” ห้ามนำค่าประมาณ เป้าหมาย ภาพแนวคิด หรือตัวอย่างสังเคราะห์มาอ้างเป็นผลการวัดจริง

07 · มาตรฐานระดับสากล: เป้าหมายที่ต้องพิสูจน์

PUI89 มุ่งพัฒนาผลิตภัณฑ์ที่สามารถทำความเข้าใจ ประเมิน และปรับปรุงตามความคาดหวังสากลที่เกี่ยวข้อง ข้อกำหนดที่ใช้จริงขึ้นอยู่กับประเภทผลิตภัณฑ์ ประเทศที่นำไปใช้ และวัตถุประสงค์

ข้อกำหนดและการตรวจสอบย้อนกลับ

เชื่อมโยงความต้องการของผู้ใช้กับข้อกำหนดระบบ การตัดสินใจออกแบบ การทดสอบ และหลักฐานก่อนเผยแพร่

การประเมินความเสี่ยงและข้อกำกับ

ระบุกฎหมาย มาตรฐาน และข้อกำหนดเฉพาะภาคส่วนที่เกี่ยวข้องก่อนใช้งาน พร้อมบันทึกช่องว่างและผู้ทบทวน

การตรวจสอบโดยหน่วยงานอิสระ

ใช้การทดสอบหรือการรับรองจากภายนอกที่มีคุณสมบัติเหมาะสมเมื่อจำเป็น และเผยแพร่เฉพาะขอบเขตและผลที่มีหลักฐานรองรับ

คำว่า “มุ่งออกแบบตามคุณภาพระดับสากล” คือหลักการพัฒนา ไม่ควรสื่อสารว่า “ได้รับการรับรองระดับสากล” “ผ่านมาตรฐาน” หรือ “พิสูจน์คุณภาพระดับโลกแล้ว” หากยังไม่มีหลักฐานรองรับ

08 · การพัฒนาโดยให้ความสำคัญกับ Open Source

เลือกใช้เครื่องมือที่โปร่งใส ดูแลรักษาได้ และทำซ้ำได้เมื่อเหมาะกับงาน ตรวจสอบใบอนุญาต แหล่งที่มา ความปลอดภัย ความเป็นส่วนตัว ทรัพยากรประมวลผล และการดูแลระยะยาวก่อนนำมาใช้ ห้ามเพิ่ม API แบบเสียค่าใช้จ่าย Cloud GPU บริการสมัครสมาชิก หรือบริการภายนอกโดยไม่ได้รับอนุมัติอย่างชัดเจน
