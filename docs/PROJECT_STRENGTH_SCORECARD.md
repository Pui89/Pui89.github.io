# PUI89 Project Strength Scorecard

**Purpose:** show the verified engineering strength of each existing PUI89 project without confusing concepts, plans, software tests, simulation results, field validation or commercial readiness.

**Current portfolio review status:** 0 completed evidence-backed strength reviews recorded for the seven listed project entries. This is a recordkeeping status; it does not mean that no engineering work or tests exist.

## Shared scoring model (100 points)

| Dimension | Weight | Evidence required |
|---|---:|---|
| Technical capability | 25 | Implemented, inspectable capabilities; versioned interfaces; reproducible demonstrations |
| Testing and evidence | 25 | Dated test runs, scope, configuration, sample counts, results, failures and traceable artifacts |
| Safety and reliability | 20 | Hazard analysis, fail-safe behavior, negative tests, human-oversight boundaries and reliability evidence |
| Engineering maturity | 15 | Integration, maintainability, reproducible setup, release discipline and operational readiness |
| Documentation and reproducibility | 10 | Architecture, requirements, instructions, provenance, licence records and repeatable evaluation |
| Real-world validation | 5 | Relevant independent or field evidence under documented conditions |
| **Total** | **100** | |

## Scoring rules

- Award points only for evidence that exists, is accessible and matches the stated project and scope.
- A planned feature, concept illustration, roadmap item, tool inventory or unrun test earns no implementation or test credit.
- Synthetic simulation results count only for the software/scenario behavior actually tested; they do not prove physical-world performance.
- Physical robot, sensor, vehicle, rescue, screening, road-safety or environmental claims require their own appropriate validation.
- Missing, stale, contradictory or unverifiable evidence receives no credit until resolved.
- Each review must record date, reviewer/scope, commit or version, evidence links, findings, limitations and next actions.
- The score is not a certification, safety approval, sales forecast, investment rating or commercial-readiness percentage.

## Review record

A completed review must include:
1. Review date and project name.
2. Defined scope and version/commit.
3. Evidence links and test conditions.
4. Points awarded per dimension with reasons.
5. Passed, failed, not-run and unknown items.
6. Risks, limitations and next actions.

**Display rule:** until a completed review is published, display **Not yet scored** and the completed-review count. Never substitute a guessed percentage.

## Relationship to other indicators

The project-strength score measures evidence-backed engineering maturity. Any commercial-readiness estimate is a separate measure with its own gates and must not be presented as this score.
