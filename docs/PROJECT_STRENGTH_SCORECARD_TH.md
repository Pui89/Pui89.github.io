# เกณฑ์ประเมินความแข็งแกร่งของโครงการ PUI89

**วัตถุประสงค์:** แสดงความแข็งแกร่งด้านวิศวกรรมของแต่ละโครงการจากหลักฐานที่ตรวจสอบได้ โดยแยกแนวคิด แผนงาน การทดสอบซอฟต์แวร์ ผลการจำลอง การทดสอบภาคสนาม และความพร้อมเชิงพาณิชย์ออกจากกันอย่างชัดเจน

**สถานะการตรวจสอบพอร์ตโฟลิโอปัจจุบัน:** ยังไม่มีรายงานการประเมินความแข็งแกร่งที่เสร็จสมบูรณ์และมีหลักฐานครบถ้วนที่บันทึกไว้ (0 รายการ) สำหรับโครงการทั้งเจ็ดรายการ สถานะนี้หมายถึงยังไม่มีการบันทึกรายงานตามเกณฑ์ ไม่ได้หมายความว่าไม่มีการพัฒนาหรือทดสอบใด ๆ

## เกณฑ์การให้คะแนนร่วม (100 คะแนน)

| ด้านการประเมิน | น้ำหนัก | หลักฐานที่ต้องมี |
|---|---:|---|
| ความสามารถทางเทคนิค | 25 | ความสามารถที่พัฒนาและตรวจสอบได้ อินเทอร์เฟซที่มีเวอร์ชัน และการสาธิตที่ทำซ้ำได้ |
| การทดสอบและหลักฐาน | 25 | ผลทดสอบที่มีวันที่ ขอบเขต การตั้งค่า จำนวนตัวอย่าง ผลลัพธ์ ข้อผิดพลาด และไฟล์หลักฐาน |
| ความปลอดภัยและความน่าเชื่อถือ | 20 | การวิเคราะห์อันตราย พฤติกรรมเมื่อเกิดข้อผิดพลาด การทดสอบกรณีลบ ขอบเขตการกำกับดูแลโดยมนุษย์ และหลักฐานความน่าเชื่อถือ |
| วุฒิภาวะทางวิศวกรรม | 15 | การบูรณาการ การบำรุงรักษา การตั้งค่าที่ทำซ้ำได้ วินัยการเผยแพร่ และความพร้อมใช้งาน |
| เอกสารและการทำซ้ำผล | 10 | สถาปัตยกรรม ข้อกำหนด คู่มือ แหล่งที่มาของข้อมูล บันทึกใบอนุญาต และการประเมินที่ทำซ้ำได้ |
| การตรวจสอบในโลกจริง | 5 | หลักฐานจากผู้ประเมินอิสระหรือภาคสนามภายใต้เงื่อนไขที่บันทึกไว้ |
| **รวม** | **100** | |

## กติกาการให้คะแนน

- ให้คะแนนเฉพาะหลักฐานที่มีอยู่ เข้าถึงได้ และตรงกับโครงการและขอบเขตที่ระบุ
- ฟีเจอร์ที่วางแผนไว้ ภาพแนวคิด รายการในแผนงาน รายการเครื่องมือ หรือการทดสอบที่ยังไม่ได้รัน จะไม่ได้คะแนนว่าเป็นสิ่งที่พัฒนาเสร็จหรือผ่านการทดสอบแล้ว
- ผลจำลองนับได้เฉพาะพฤติกรรมของซอฟต์แวร์หรือสถานการณ์ที่ทดสอบจริง ไม่ใช่หลักฐานยืนยันประสิทธิภาพในโลกจริง
- การกล่าวอ้างเกี่ยวกับหุ่นยนต์ เซนเซอร์ ยานพาหนะ การกู้ภัย การคัดกรอง ความปลอดภัยบนถนน หรือสภาพแวดล้อม ต้องมีการตรวจสอบที่เหมาะสมแยกต่างหาก
- หลักฐานที่ขาดหาย ล้าสมัย ขัดแย้ง หรือตรวจสอบไม่ได้ จะยังไม่ได้รับคะแนนจนกว่าจะแก้ไข
- รายงานแต่ละครั้งต้องระบุวันที่ ผู้ตรวจสอบหรือขอบเขต เวอร์ชันหรือ commit ลิงก์หลักฐาน ข้อค้นพบ ข้อจำกัด และขั้นตอนถัดไป
- คะแนนนี้ไม่ใช่การรับรอง การอนุมัติความปลอดภัย การคาดการณ์ยอดขาย การจัดอันดับการลงทุน หรือเปอร์เซ็นต์ความพร้อมเชิงพาณิชย์

## ข้อมูลที่ต้องมีในรายงาน

1. วันที่ตรวจสอบและชื่อโครงการ
2. ขอบเขตและเวอร์ชัน/commit ที่ตรวจสอบ
3. ลิงก์หลักฐานและเงื่อนไขการทดสอบ
4. คะแนนแต่ละด้านพร้อมเหตุผล
5. รายการที่ผ่าน ไม่ผ่าน ยังไม่ได้ทดสอบ และยังไม่ทราบ
6. ความเสี่ยง ข้อจำกัด และขั้นตอนถัดไป

**กติกาการแสดงผล:** หากยังไม่มีรายงานที่เสร็จสมบูรณ์ ให้แสดง **ยังไม่มีคะแนน (Not yet scored)** พร้อมจำนวนรายงานที่เสร็จสมบูรณ์ ห้ามใช้เปอร์เซ็นต์ที่คาดเดาขึ้นเอง

## รายการโครงการในพอร์ตโฟลิโอ

ทั้งเจ็ดรายการ ได้แก่ Coconut Harvest AI, Extreme Flood Rescue AI, PUI89 Sentinel — Multimodal Screening AI, PUI89 AI HOME, PUI89 AI NOMAD, PUI89 AI Robot Car และ PUI89 AI Robot Motorcycle โดย HOME และ NOMAD ยังคงเป็นหนึ่งกลุ่มโครงการ แต่สามารถมีรายงานตรวจสอบแยกกันได้เมื่อขอบเขตหลักฐานแตกต่างกัน

## ความแตกต่างจากตัวชี้วัดอื่น

คะแนนความแข็งแกร่งของโครงการใช้วัดวุฒิภาวะทางวิศวกรรมจากหลักฐาน ส่วนเปอร์เซ็นต์ความพร้อมเชิงพาณิชย์เป็นตัวชี้วัดอีกประเภทหนึ่ง มีเกณฑ์ของตนเอง และห้ามนำมาแสดงแทนคะแนนนี้
