01 / เกษตรกรรม

Coconut Harvest AI

ระบบ AI สำหรับวิเคราะห์ระยะของมะพร้าว 3 กลุ่ม ได้แก่ มะพร้าวเขียวแก่ มะพร้าวสีเหลือง และมะพร้าวแก่สีน้ำตาล

ช่วงความสูงต้นมะพร้าว 0–30 เมตรเป็นเป้าหมายการออกแบบระยะยาว ยังไม่ได้ยืนยันความสามารถในการจำแนกระยะ ตรวจจับ เอื้อมถึง หรือเก็บเกี่ยวจริง แขนกลและตะกร้าเก็บผลผลิตเป็นแนวคิดที่ต้องผ่านการออกแบบทางวิศวกรรมและการทดสอบความปลอดภัย

02 / ภัยพิบัติ

Extreme Flood Rescue AI

การวางแผนและจำลองสถานการณ์น้ำท่วมช่วง 0–15 เมตร เพื่อศึกษาการสำรวจพื้นที่ การทำแผนที่อันตราย และการสนับสนุนการตัดสินใจโดยมนุษย์ แนวคิดหุ่นยนต์กู้ภัยรุ่นนี้ใช้ตัวเรือทรงแพหรือเรือขนาดกะทัดรัด พร้อมล้อที่พับเก็บได้ โดยกางล้อเมื่อเคลื่อนที่บนบกหรือบริเวณน้ำตื้นที่เหมาะสม และพับเก็บในช่องป้องกันเมื่อลอยน้ำ

แพลตฟอร์มมีแนวคิดรองรับผู้ประสบภัย สัตว์ในพื้นที่แยกที่ปลอดภัย และอุปกรณ์ช่วยเหลือ ส่วนระบบขับเคลื่อนในกระแสน้ำ การทรงตัว น้ำหนักบรรทุก ระดับขอบเรือ และความปลอดภัยขณะเปลี่ยนโหมดต้องผ่านการวิเคราะห์และทดสอบแบบไร้คนโดยเป็นขั้นตอนก่อน ระดับน้ำ 0–15 เมตรเป็นเพียงสถานการณ์จำลอง ไม่ใช่พิกัดความลึกหรือความสามารถในการจมน้ำของตัวเรือ และยังไม่มีการยืนยันการใช้งานในกระแสน้ำเชี่ยวหรือการขนส่งผู้โดยสารจริง

03 / การตรวจคัดกรอง

Multimodal Narcotics Screening AI

แนวคิดผู้ช่วยตรวจคัดกรองแบบเคลื่อนที่ สำหรับตรวจทานหลักฐานหลายรูปแบบที่ได้รับอนุญาต เช่น ภาพ RGB และอาจรวมภาพเอกซเรย์หรือผลจากเซนเซอร์เคมีที่ผ่านการตรวจสอบแล้ว เมื่อมีอุปกรณ์และชุดข้อมูลที่เหมาะสม แต่ละรูปแบบข้อมูลและการผสานข้อมูลต้องได้รับการประเมินแยกกัน

แยกอุปกรณ์บุหรี่ไฟฟ้าออกจากหมวดสารเสพติดอย่างชัดเจน รูปลักษณ์เพียงอย่างเดียวไม่สามารถยืนยันส่วนประกอบของน้ำยาหรือชนิดสารเคมีได้ การแจ้งเตือนจาก AI ไม่ใช่หลักฐานยืนยันว่ามีสารเสพติด และระบบจะไม่กล่าวหา กักตัว ตรวจค้น หรือบังคับใช้กฎหมายโดยอัตโนมัติ การตัดสินใจที่มีผลกระทบต้องดำเนินการโดยเจ้าหน้าที่ผู้มีอำนาจตามกฎหมาย ระบบตรวจจับยังไม่ได้ผ่านการรับรอง

พื้นฐานวิศวกรรมร่วมของ PUI89

แนวทางของ PUI89 คือพัฒนาพื้นฐานซอฟต์แวร์ AI ร่วมกัน แล้วต่อยอดเป็นหกกลุ่มโครงการเฉพาะทาง งาน shared core กำลังทยอยพัฒนาและตรวจทาน ส่วนนี้อธิบายทิศทางสถาปัตยกรรม ไม่ใช่การยืนยันว่าทุกส่วนเชื่อมต่อหรือผ่านการตรวจสอบแล้ว

ติดตามสถานะและความไม่แน่นอน

ติดตามแหล่งที่มาของข้อมูล เวลา ระดับความเชื่อมั่น สถานะการสอบเทียบ ข้อมูลที่ล้าสมัย และหลักฐานที่ขัดแย้งกัน พร้อมแทนสถานะของสภาพแวดล้อมอย่างเป็นระบบ ส่งต่อความไม่แน่นอนไปยังแผนงาน และขอให้มนุษย์ตรวจสอบเมื่อหลักฐานไม่ครบถ้วนหรือไม่น่าเชื่อถือ

ทดสอบและรายงานข้อผิดพลาด

ใช้การทดสอบ Python ที่ทำซ้ำได้และรายงานแบบมีโครงสร้าง ผลทดสอบซอฟต์แวร์ไม่ใช่หลักฐานยืนยันสมรรถนะภาคสนามหรือความปลอดภัยของหุ่นยนต์จริง

แยกข้อเสนอจากการสั่งงานจริง

แยกการรับรู้ข้อมูล การติดตามสถานะสภาพแวดล้อม การวางแผนงาน การเฝ้าระวังความปลอดภัย และการสั่งงานฮาร์ดแวร์ออกจากกัน เริ่มจากการจำลองและการตรวจสอบโดยมนุษย์ก่อนพิจารณาทดลองกับฮาร์ดแวร์

Agentic AI, VLM และ VLA — แผนประเมินเป็นลำดับ

จะศึกษากระบวนการทำงานแบบ Agentic AI, โมเดล Vision-Language Model (VLM) และอินเทอร์เฟซจำลอง Vision-Language-Action (VLA) หลังจากพื้นฐานการทดสอบ Python และการรายงานมีความเสถียรก่อนเท่านั้น โดยต้องตรวจสอบใบอนุญาต ขนาดไฟล์ดาวน์โหลด ความต้องการ RAM/VRAM และค่าใช้จ่ายก่อน จากนั้นจึงทดลองในระบบจำลองพร้อมการอนุมัติจากมนุษย์ ข้อความนี้เป็นแผนงาน ไม่ได้หมายถึงดาวน์โหลดโมเดล ใช้ API แบบเสียค่าใช้จ่าย หรือควบคุมหุ่นยนต์จริงแล้ว
