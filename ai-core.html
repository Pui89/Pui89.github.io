PUI89 / Shared Engineering Foundation

Shared AI Core

A common software foundation for PUI89 AI applications, mobile assistant robots and intelligent vehicle research. The aim is to reuse trustworthy interfaces and evidence practices without forcing every project to use the same sensors, models or physical design.

Architecture and integration work in progress · not a standalone certified product

What the shared core provides

Projects should share dependable software contracts, safety checks, evidence handling and evaluation conventions. Each project keeps its own domain logic, model selection, sensor assumptions and hardware boundaries.

01 / Contracts

Machine-readable interfaces

Versioned WorldState, Observation, ActionProposal and FailureReport structures make inputs, proposed actions, uncertainty and failures explicit.

02 / Evidence

Evidence integrity

Track source, timestamp, provenance, freshness, missing data, conflicts and changes. Separate measured facts from estimates, assumptions and recommendations.

03 / Safety

Proposal-only safety gates

Validate schemas and operating limits, reject invalid or stale proposals, require human review where appropriate, and default to safe stop or no action when evidence is inadequate.

04 / Evaluation

Reproducible benchmarks

Use deterministic scenarios, versioned test records, failure reports and before/after comparisons. A passing software test is not proof of real-world performance.

05 / Model adapters

Replaceable AI components

Connect suitable non-Chinese, license-reviewed open models through project-specific adapters. Model availability does not imply local compatibility, accuracy or safe deployment.

Common processing workflow

1. ObserveCollect available sensor, user or dataset inputs.
2. ValidateCheck schema, provenance, freshness and quality.
3. UnderstandEstimate state and uncertainty using project adapters.
4. ProposeGenerate bounded recommendations, not direct actuation.
Physical robot and vehicle control is outside the authority of this shared advisory layer. Any future actuation requires a separately engineered, tested and approved control and safety system.

What every project report should answer

Evidence status

  • What is known?
  • What is missing or uncertain?
  • What changed, and from which source?

Decision quality

  • What may fail or deteriorate?
  • What is recommended, and why?
  • What evidence proves an improvement?

Implementation boundary

This page describes the shared architecture direction and reusable engineering principles. Integration status differs by repository and component. It does not claim that every model, sensor, robot, vehicle or adapter is already integrated, trained, validated or operational. Check each repository's tests, evidence and current status before relying on a capability.
