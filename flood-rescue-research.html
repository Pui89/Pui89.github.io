Flood Rescue AI: perception and terrain research

A technical overview of how PUI89 is structuring evidence for flood-scene understanding: terrain context, changing video observations, segmentation quality and uncertainty. The work is software-first and simulation-oriented.

Development status and safety boundary. The items below describe research code, candidate methods and draft pull requests. They are not a deployed flood-warning service, a validated rescue robot, a calibrated water-depth instrument or proof of safe routes. Some work remains under review; tests and field validation must be checked in the linked records.
01 · LIDAR / TERRAIN

Terrain context and drainage indicators

The research scaffold examines gridded elevation data, NoData handling, local slope, D8 flow direction and flow accumulation. These can help organise terrain evidence and identify areas for further hydrological review; they do not independently predict flood depth, current speed or a safe rescue path.

Status: prototype code on a review branch; real LiDAR ingestion and hydrological validation are not established.

02 · VIDEO / TEMPORAL EVIDENCE

Video tracking and changing observations

A temporal evidence ledger can record frame references, supplied track identities, gaps and label conflicts for human review. This is a foundation for evaluating continuity over time, not a video decoder, object detector or production tracker.

Status: software scaffold on a review branch; no real flood-video performance is claimed.

03 · SEGMENTATION / EVALUATION

Measure segmentation quality

The benchmark scaffold defines confusion-matrix-based pixel accuracy, per-class intersection over union (IoU), Dice, precision and recall, plus supplied-match diagnostics for identity switches and track fragmentation. Metrics require suitable labelled reference data and must be interpreted per class and scenario.

Status: evaluation code and protocol proposed in a draft pull request; tests have not been represented as run.

04 · DEPTH / MODEL CANDIDATE

Relative depth is not flood depth

Depth Anything V2 Small is documented as a candidate for relative scene-depth cues. Monocular relative depth is not automatically metric distance, water-surface elevation or calibrated flood depth. Any use requires domain-specific calibration, reference measurements and error evaluation.

Status: model candidate documented for review; weights have not been downloaded and no inference integration is claimed.

Evaluation principles

  • Keep source, timestamp, coordinate/frame reference, label provenance and uncertainty attached to observations.
  • Report missing, stale, noisy and conflicting sensor evidence rather than silently filling gaps.
  • Separate measured values from relative estimates and proposed interpretations.
  • Use scenario-specific held-out data; report class imbalance and failure cases, not only aggregate scores.
  • Require human review for rescue decisions. Do not issue physical robot commands from this research page or its software scaffolds.

What would count as stronger evidence?

Versioned datasets with lawful provenance; reviewed annotations; reproducible test commands and results; calibration against independent measurements; robustness tests for rain, glare, occlusion, night scenes, sensor dropout and conflicting inputs; and carefully supervised simulation and field studies. Until those records exist, capability remains unverified.
