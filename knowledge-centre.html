04 / EVIDENCE STANDARD

How PUI89 reports technical progress

ImplementedCode or an artefact exists; link to the exact repository path or release.
TestedA repeatable test was run; state environment, command, date and result.
MeasuredA defined instrument or data source produced a result under a stated protocol.
Simulated / syntheticLabel generated scenarios and simulated results; never present them as field observations.
Proposed / plannedDescribe future work without implying implementation or demonstrated performance.
Unknown / not verifiedMake missing evidence, limitations and unresolved risks visible.

Passing software tests does not prove field reliability, physical robot safety, energy savings or operational readiness. Those claims require appropriate validation.

05 / RESEARCH WORKFLOW

From question to reproducible evidence

  1. Frame a questionDefine the problem, user, scope and measurable outcome.
  2. Review primary sourcesRecord authors, date, version, licence and relevance.
  3. Specify a baselineDocument data, environment, metrics and comparison protocol before changing the system.
  4. Run a small experimentPrefer no-cost tools and existing hardware. Check cost, licence and resource impact before downloading models or installing large packages.
  5. Publish evidenceLink code, tests, results, limitations and known failures.
  6. Review before integrationRequire human approval for safety-critical, external or destructive actions.
