Three applied challenges. One engineering approach.

Our common platform direction is to make AI-assisted workflows more testable and useful: record the state of the system, expose uncertainty, test failure cases, and publish what the evidence does—and does not—show.

01 / AGRICULTURE

Coconut Harvest AI

Exploring computer vision, orchard-image quality, harvest-planning workflows, and the requirements for a future harvesting robot.

What support can help unlock

We focus on milestones that can be inspected and reviewed—not broad claims about future performance. Each work package needs an agreed scope, owner, acceptance criteria, and reporting method.

01

Build a trustworthy coconut benchmark

Audit data permissions, review annotations, establish a leakage-aware held-out set, and publish measured baseline results and failure cases—or record why evaluation remains blocked.

02

Make autonomy tests reproducible

Run documented scenarios for sensor faults, missing inputs, lost communications, low confidence, safe hold, and recovery. Separate deterministic outcomes from host-dependent timing.

03

Learn from real agricultural workflows

Talk with growers and agricultural specialists, define one practical workflow, agree data permissions, and measure whether human-reviewed software helps.

04

Prepare the simulation pathway

After the lightweight Python suite passes, select one compatible simulator and integrate one robot and one sensor at a time. Hardware trials are a separate decision and require independent risk review.

How we protect partner trust

Evidence over hype

We distinguish implemented code, passed software tests, simulation, measured model performance, and field validation.

Clear scope and accountability

Any funded work should have written goals, deliverables, resource and funding limits, data rights, ownership terms, and a reporting plan.

Responsible deployment

Prototype concepts are not represented as certified physical systems. Consequential decisions need appropriate human oversight and independent safeguards.

Verify every offer independently

Check the sender's organisation, domain, role, and public history. Contact the organisation using contact details you find independently—not only details in an unsolicited message.

Never share account secrets

PUI89 will never ask for your password, one-time passcode, recovery code, private SSH key, or API token. Do not send these to anyone claiming to represent PUI89.

No guaranteed funding or investment claims

Be cautious of guaranteed grants, investment, awards, accelerator admission, or contracts that require an upfront release, processing, or verification payment. Verify all terms in writing.

Protect project information

Do not publish private datasets, personal information, credentials, unreleased designs, or sensitive operational details in public issues or community posts. Review data and software licences before reuse.

Written terms before collaboration

Before money, equipment, data, or code changes hands, agree in writing on scope, deliverables, funding and resource commitments, ownership, licence, confidentiality, and exit terms. Seek independent legal advice for material agreements.
