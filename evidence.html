Evidence before claims

Evidence & Progress

A concise index of the evidence behind PUI89's six product concepts: what is currently documented, what remains unproven, and what should be validated next.

Important: A concept page, design requirement, source-code check or successful software workflow does not prove AI accuracy, physical performance, operational safety, field readiness or certification. No product is presented here as field-validated or commercially released.

Six product evidence summaries

These are conservative evidence boundaries, not readiness scores. Detailed records belong with each product's own documentation and test reports.

Implemented — software foundation

01 · Coconut Harvest AI

Implemented scope: software and evaluation-preparation components for coconut maturity assessment. The harvesting workflow remains a proposal.

Not demonstrated: validated detection accuracy, reliable height/distance performance, safe harvesting or field productivity.

Next evidence: traceable real-image datasets, human-reviewed labels, repeatable CPU-based evaluation and controlled component tests.

02 · PUI89 Sentinel

Current portfolio scope: a four-legged quadruped All-Terrain Exploration & Inspection Robot for environmental awareness, multimodal sensor evidence collection and human-supervised inspection.

Not demonstrated: real-world locomotion, terrain traversal, environmental-perception accuracy, durability, operational safety or field performance.

Next evidence: define the first supervised inspection mission, operating envelope, site hazards, sensor requirements and measurable acceptance criteria; then plan simulation, bench and controlled prototype tests.

Evidence record — 20 Nov 2026: Sources: Sentinel README and scope migration register. Method: documentation review only. Test/run ID and measured result: not applicable; no physical or field test is claimed.

Limitations: no physical prototype, integrated sensor suite, validated locomotion, terrain performance, durability or field-safety result is established.

How to read evidence

Use the label that matches the strongest traceable evidence—not the ambition of the project.

SpecifiedRequirements and acceptance criteria are documented.
Software-testedDefined software checks passed; this says nothing by itself about physical performance.
Bench / simulatedComponent or simulated scenarios were tested under stated conditions.
Field-validatedRepeatable real-world trials support the specific claim. No such status is claimed here.

Source records

Inspect the underlying project documentation and test definitions. Each record should include its date, commit or run identifier, method, result and limitations.
